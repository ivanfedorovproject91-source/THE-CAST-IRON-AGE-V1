# Генеральный директор и «Кабинет» — аудит и архитектура

## Результаты аудита (этап 1)
- **Рабочий код — `js/` и `css/`.** `index.html` подключает только их. Копии `config.js`, `engine.js`, `ui.js`, `data_actions.js`, `style.css` в корне репозитория устарели и не используются; не трогаем.
- **Лестница.** `career_ladder.js` переопределяет `K.checkLadder/applyAttest/reqLines`, `G.rankName/jobTitle/monthlyPay/rankInfo`. Ранг 10 = «Заместитель генерального директора» (5 ступеней `mgmtStage`). После ступени 5 `currentTarget()` возвращает `null` — дальше хода нет. Старый `K.promote` (концовка «Начальник цеха», потолок 9) — мёртвый код, т. к. `K.applyAttest` переопределён.
- **Противоречия.** (1) `D.RANKS[10]` и `D.MGMT_PAY[10]` ещё описывают зама, а `ROLES[10].unlock` обещает «кабинет генерального директора» — его нет. (2) Концовки `puppet`/`head` объявлены, но нигде не вызываются. (3) `ui.fileTab` показывает цель только при `rank < 10`.
- **Зависимости от `car.rank`:** оклад, фамильярность (v38), романтика, события, `fireRisk`, `ojScore`. Поэтому числовые ранги **не меняем**: статус директора — отдельная модель `s.ceo.appointed`.
- **Время.** Единственная точка смены дня — `G.sleep()` (`t.day++`, затем `G.weeklyTick()` по понедельникам, `G.dailyTick()`, `G.startDay()`). Больше нигде день не увеличивается. Именно сюда подключаемся.
- **Деньги.** Личные — `s.money/s.debt/s.loans`, зарплата через `G.payday` (по пятницам). Корпоративных денег в игре нет.
- **Сохранения.** `G.save/G.load/G.migrate` — автослияние `baseState()` в старое сохранение; `SAVE_VERSION` не меняем.
- **Навигация.** `ui.js`: `navHTML()` (жёсткий список из 6 вкладок) и `gameScreen()` (`switch(UI.tab)`). Нужны две минимальные правки в `ui.js`.
- **Концовки.** `G.end('fired')` перехватывается в `data_actions.js` (взятка Труханову) — для директора перехватываем раньше и превращаем в увольнение советом.

## Архитектура (этап 2)
`s.ceo` — сюжет и статус (`appointed`, `stage`, `support`, …), создаётся для всех (пустой).
`s.company` — `null` до назначения; создаётся при вступлении в должность. Личный и корпоративный счета разделены: `s.money` ≠ `s.company.treasury`.

| Файл | Ответственность |
|---|---|
| `js/company.js` | ядро `G.co`: модель, форматирование, тик (`process`), отчёты, расчёт доверия |
| `js/company_production.js` | подразделения, выпуск, износ, поломки, ремонт, проекты развития |
| `js/company_finance.js` | бюджет, кредиты, вклады, задолженность, налоги, недельное закрытие |
| `js/company_staff.js` | руководители, кадровые решения |
| `js/company_supply.js` | ресурсы, поставщики, заказы |
| `js/company_sales.js` | покупатели, контракты, отгрузки, возвраты |
| `js/company_events.js` | директорские события, решения, совет директоров |
| `js/ceo.js` | назначение: условия, сюжетная цепочка, приказ, вступление; перехват концовок |
| `js/company_ui.js` | вкладка «Кабинет», 9 разделов |

**Часы.** `G.dailyTick` оборачивается: после оригинала вызывается `G.co.process()`. Он обрабатывает дни `(lastDay, t.day]` по одному (не более 14 за раз, при «откате» даты — только сброс метки). Метка `lastDay` пишется в то же сохранение, что и `t.day`, поэтому перезагрузка не может начислить период дважды. Рендер ничего не мутирует; события создаются только в тике и хранятся в `company.pending` с id (дубли невозможны).

**Экономика (в неделю, норма).** Выпуск ≈ 475 т, цена ≈ 56–60 тыс. ₽/т, себестоимость ≈ 53 тыс. ₽/т → маржа 5–9 %. Цепочка: плавка → литьё → механика; сырьё и комплектующие списываются при выпуске; нехватка сырья/людей/состояния оборудования режет выпуск; рост плана повышает износ, риск поломок и брак.
